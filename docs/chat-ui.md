# 聊天消息展示

聊天布局位于 `crates/hikari/src/chat.rs`。展示状态单独保存在每个会话的 `ChatState` 中，不改写原始 provider transcript。

- 用户输入使用右侧气泡，按原始文本显示；助手正文使用 GPUI-kit 的 GFM Markdown 组件，支持标题、列表、引用、表格、链接和代码块。
- 每轮最后一个有效助手回答保留在正文区域，中间说明、思考和工具调用放入“执行过程”。完成后默认收起过程；运行中展开过程；工具失败时默认展开，显示失败数量与错误输出。用户手动选择的展开状态优先。
- 连续工具调用按批次展示，单个工具详情默认收起。参数与输出分别保留，历史加载从 assistant tool calls 恢复参数；输出作为字面代码显示，避免其中的 Markdown、HTML 和代码围栏影响消息结构。
- 思考单独折叠，过滤无正文、无思考的助手占位消息。最终回答、代码块和工具输出提供复制入口。工具输出与长代码块内部滚动。
- 会话保留滚动位置；接近底部时跟随流式更新，向上阅读历史时不强制回到底部。折叠入口支持鼠标、Tab、Enter 和 Space，并提供辅助技术所需的展开状态。

## 验证

```powershell
cargo check -p hikari
cargo test -p hikari
cargo test -p hikari chat_ui_interactions -- --ignored --nocapture
```

最后一项需要 Windows 桌面会话和 GPU，使用隔离在 `target/chat-test-data` 的固定数据，绘制真实 GPUI 帧并通过 GPUI 命中测试分发鼠标与键盘事件。覆盖深浅色主题、Markdown、过程/工具/思考折叠、失败状态、消息事件更新和输入框向上增高/内部滚动；另核对工作区与默认目录隔离、终端切换、会话草稿/重命名/置顶/删除，以及提供商密钥保存恢复。GPUI 当前 Windows 后端不支持 `render_to_image`，此测试不生成像素截图。

运行 `cargo run` 可检查实际会话。视觉验收重点：正文与输入框宽度对齐、长工具输出不挤占整个会话、折叠后最终回答完整可读，以及深浅色主题的代码块和表格对比度。图片附件与独立 artifact 消息尚未接入运行时协议，本次处理现有文本、思考与工具消息。
